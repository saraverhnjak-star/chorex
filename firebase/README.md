# Local Firebase infrastructure

`firebase.json` binds Auth (9099), Firestore (8080), Functions (5001), UI (4000), hub (4400), and logging (4500) to loopback. The `dev` alias selects `chorex-dev`. Java 21+ is required for Firestore with the pinned Firebase CLI.

Run `pnpm emulators:start` from the root. The bounded `pnpm emulators:verify:create-family`, `pnpm emulators:verify:create-child`, `pnpm emulators:verify:create-pairing-session`, and `pnpm emulators:verify:redeem-pairing-session` commands exercise the implemented Phase 1 callables and their rules against disposable emulator data. Environment guards reject other project IDs or endpoints before any request. Authentication in rules checks uses official authenticated test contexts. Rules are loaded from the CLI configuration, not replaced by tests.

Pairing redemption requires the server secret `PAIRING_RATE_LIMIT_HMAC_SECRET`. Production must provide it through Firebase Secret Manager. For local verification, copy `functions/.env.local.example` to the ignored `functions/.env.local` and replace its emulator-only placeholder; `functions/.secret.local.example` documents the corresponding local secret binding. CI writes the same non-production test value to both ignored files before starting the suite. Never commit a real secret. The Functions implementation reads the emulator-only variable, uses one fixed local rate-limit bucket because the callable emulator does not expose request IP fields, and emits the Auth emulator's local fake custom-token format only when `FIREBASE_AUTH_EMULATOR_HOST` is present. Production requires the platform request IP, the bound secret, and Firebase Admin token minting.

Rules allow a signed-in user to read their own profile and active Family members to read the Family and its membership subcollection. All client writes and other reads remain denied. No deployment command is provided.

For a physical device, deliberately change the emulator `host` bindings to your machine's private LAN IPv4 address and set that same address in the app environment. This exposes local emulator services to your LAN; use a trusted network. The automated check intentionally accepts only the checked-in loopback configuration.
